# 《坦克防线》网页小游戏技术设计文档

> 文档版本：v0.6（关卡与奖励机制修订稿）
> 编写日期：2026-08-21
> 项目类型：单机、俯视角、网页端、像素复古 + 现代扁平 UI
> 目标平台：网页端（首版以桌面浏览器为验收范围）
> 正式项目名：坦克防线

---

## 1. 文档目标

本文档用于在正式编码前确定产品范围、核心玩法、视觉风格、技术架构、数据结构和验收标准。它不是最终需求冻结稿，后续可以继续修改。

首版目标是通过六个短关卡完成一局节奏明快的坦克战斗，同时具备：

- 四方向移动、射击、生命值、得分和明确的胜负判定。
- 敌方坦克的巡逻、转向、追踪和射击行为。
- 砖墙、钢墙、水域、草地等具有不同规则的地形。
- 地图中央以砖墙或障碍物组成清晰可辨的 `LXY` 标识。
- 地图底图使用“浪尖大学社区”完整文字作为主题背景素材。
- 每关结束三选一技能，让玩家逐步形成不同战术组合。
- 像素战场与现代扁平 HUD 相结合，兼顾复古感和可读性。

## 2. 需求解释与待确认项

### 2.1 当前采用的解释

- 姓名缩写使用 `LXY`，界面展示不强制大小写；地图数据统一使用小写资源标识 `lxy`。
- “浪尖大学社区”按用户最终确认的完整文字绘制在底图上。
- 首版仅交付网页版本，以桌面浏览器键盘操作为强制验收项；移动浏览器适配不阻塞首版发布。
- 首版尽量上线完整技能池，当前实现 17 种技能；仍以“一个弹药槽 + 一个主动槽”控制操作复杂度。
- 美术素材使用 AI 生成素材，或使用 AI 辅助搜索到且授权清晰的模板素材。
- 首版只制作音效，不制作背景音乐。
- 代码托管于 GitHub，并通过 GitHub Pages 发布可访问的网页版。
- 游戏采用非写实、无血腥表现：坦克被击毁时只显示像素爆炸、碎片、震屏和分数。
- 首版以单人 PvE 为主，不把联网联机作为首发阻塞项。

### 2.2 设计边界

- 可以借鉴经典品类机制，但不复制其他游戏的地图、角色、图标、音效或品牌素材。
- “浪尖大学社区”文字将采用程序绘制、AI 生成或项目自制字图，不直接使用来源不明的图片。
- AI 搜索到的模板必须确认允许修改和发布；优先使用 CC0、SIL OFL 或明确允许商业/非商业项目使用的许可，并在 `ASSET_LICENSES.md` 中记录来源。
- 所有技能先以可配置数据实现，便于后续平衡和增删。

## 3. 玩法参考与原创组合

本项目不复刻某一款现有游戏，而是组合三类已被验证的玩法：

- 经典守基地：借鉴《Battle City》的“保护基地、破坏砖墙、利用地形开辟路线”思路。Nintendo 官方页面对其核心描述就是控制坦克、守住总部，并通过破墙和地形获得战术优势。
- 迷宫弹道：借鉴迷宫坦克游戏中“炮弹碰墙反弹、利用角度攻击掩体后目标”的博弈，但限制反弹次数，避免画面失控。
- 现代短局与构筑：参考现代坦克竞技游戏常见的短局、多模式、武器差异和升级选择，让玩家在一局内形成不同流派。

本项目的原创核心组合为：

> 守护“浪尖核心” + 可破坏 LXY 地图签名 + 逐关技能构筑 + 单 Boss 决战 + 浪尖共鸣。

- [Nintendo 日本：Battle City 操作与胜负说明](https://www.nintendo.co.jp/wii/vc/vc_bc/vc_bc_02.html)

## 4. 产品定位

### 4.1 核心体验

玩家驾驶一辆像素坦克，在固定俯视角地图中保护“浪尖核心”，依次完成六个独立关卡。玩家可以破坏砖墙改变路线、借钢墙反弹炮弹、利用草地隐藏、绕过水域，并在每关结束后从三项技能中选择一项形成战术组合。

### 4.2 单局节奏

- 教学阶段：约 20～30 秒。
- 标准关卡：约 3～5 分钟。
- Boss 关卡：约 5～7 分钟。
- 无尽模式：持续到玩家生命耗尽或基地被摧毁。

### 4.3 目标用户

- 喜欢经典坦克大战和复古像素游戏的玩家。
- 喜欢短局、技能组合和轻策略的休闲玩家。
- 使用电脑浏览器访问的大学生用户；移动浏览器支持作为后续增强项。

## 5. 游戏循环

单局完整流程：

1. 进入标题页，选择模式和难度。
2. 查看操作提示与本关目标。
3. 玩家出生并获得 2 秒无敌保护。
4. 当前关卡的敌人按配置依次出现，普通关不生成 Boss。
5. 玩家移动、射击、利用地形和技能消灭敌人。
6. 每关结束给予分数、少量修复奖励，并在三选一技能中选择一项强化。
7. 选定技能后进入下一关；第六关击毁唯一的潮汐巨兽后胜利。
8. 结算击毁数、命中率、连击、剩余生命、最高分和本局技能。

核心短循环：

> 观察敌情 → 移动找角度 → 射击/技能 → 清除本关 → 三选一强化 → 进入下一关。

## 6. 游戏模式

### 6.1 首版必做：守卫模式

- 玩家保护地图底部中央的“浪尖核心”。
- 共 6 个独立关卡，前 5 关没有 Boss。
- 第 6 关只出现一只潮汐巨兽，击败后结算胜利。
- 玩家生命归零或核心生命归零即失败。
- 标准难度每局约 4 分钟。

### 6.2 首版建议：无尽模式

- 敌人持续刷新，强度每波提高。
- 每 3 波出现精英坦克，每 5 波出现 Boss。
- 记录本地最高分、最高波次和最长连击。
- 适合反复游玩和展示技能组合。

### 6.3 后续扩展

- 限时歼灭：在倒计时结束前获得目标分数。
- 据点争夺：占领地图中央区域并累计控制时间。
- 生存缩圈：安全区逐渐缩小，迫使玩家移动。
- 双人本地合作：两名玩家共同守卫基地。
- Boss Rush：连续挑战具有独特技能的 Boss。
- 每日挑战：固定地图、固定技能池、统一排行榜规则。

## 7. 操作设计

### 7.1 桌面端默认键位

- `W/A/S/D` 或方向键：四方向移动。
- `Space`：发射主炮，作为唯一默认射击键。
- `Q`：使用当前主动技能。
- `E`：切换已装备的弹药技能。
- `R`：放置型技能，例如地雷或修复墙。
- `Esc` 或 `P`：暂停。
- `M`：静音切换。

### 7.2 操作规则

- 坦克只能朝上、下、左、右四个方向移动。
- 坦克停止后仍保持最后朝向，炮弹沿该方向发射。
- 同时按两个方向时，优先采用最后按下的方向，避免斜向移动。
- 移动起步提供极短加速过渡，但碰撞盒保持格子化，保证操作清晰。
- 玩家持续按住射击键时，按照武器射速自动开火。
- 受击、拾取、技能冷却完成均有画面、声音和 HUD 三重反馈。

### 7.3 移动端横屏（后续增强）

- 左下角为四方向虚拟摇杆，吸附到四方向。
- 右下角为射击按钮，右侧上方为技能按钮。
- 操作区半透明，触摸时提高不透明度。
- 首版不把移动端作为发布阻塞项；桌面网页版稳定后再进行触摸操作和横屏适配。

## 8. 玩家系统

### 8.1 基础属性建议

- 最大生命值：5。
- 初始移动速度：120 像素/秒。
- 普通炮弹伤害：1。
- 普通炮弹速度：360 像素/秒。
- 基础射击间隔：420 毫秒。
- 同屏普通炮弹上限：3。
- 受击无敌：800 毫秒。
- 出生保护：2 秒。

以上数值必须放在配置文件中，不写死在业务代码里。

### 8.2 受击反馈

- 玩家坦克闪白 100 毫秒。
- 屏幕轻微震动 80～120 毫秒。
- 生命条立即减少，并显示短暂红色残影。
- 坦克周围出现方向性火花，提示攻击来源。
- 低生命值时屏幕边缘出现轻微红色脉冲，但不能遮挡地图。

### 8.3 连击与得分

- 普通坦克：100 分。
- 快速坦克：150 分。
- 重装坦克：250 分。
- 精英坦克：500 分。
- Boss：2000 分。
- 3 秒内连续击毁敌人可维持连击。
- 连击倍率建议为 `1.0 → 1.2 → 1.5 → 2.0`，最高 2 倍。
- 保护基地无伤、命中率超过 70%、保留 LXY 结构等可提供结算加分。

## 9. 敌方坦克设计

### 9.1 敌人类型

普通巡逻坦克：

- 生命 1，速度普通，低频射击。
- 主要作用是教学和制造基础压力。

快速侦察坦克：

- 生命 1，速度快，转向频繁。
- 偏好从侧路接近基地或抢夺技能箱。

重装坦克：

- 生命 3，速度慢，炮弹伤害高。
- 会主动破坏阻挡路线的砖墙。

狙击坦克：

- 生命 1，移动少，射程长，射击前出现红色瞄准线。
- 给玩家 600～900 毫秒躲避窗口。

反弹坦克：

- 生命 2，炮弹最多反弹 1 次。
- 优先寻找能通过墙面折射命中玩家的位置。

潮汐巨兽（非坦克 Boss）：

- 生命 16，外形为紫色软体巨兽、触须和青色独眼，与机械坦克明显区分。
- 普通攻击为三方向潮汐弹；特殊攻击先蓄力 780 毫秒，再发射八方向环形弹幕。
- 半血后缩短特殊攻击间隔，但蓄力光圈和文字预警保持不变。
- 作为第六关唯一的最终 Boss，为坦克战加入轻量“怪兽入侵”变化。

### 9.2 AI 状态机

每辆敌方坦克使用有限状态机，不采用昂贵的逐帧全图寻路。

- `SPAWN`：出生动画和短暂无敌。
- `PATROL`：沿预设节点或可行方向巡逻。
- `INVESTIGATE`：前往最近一次听到炮声或看到玩家的位置。
- `CHASE`：发现玩家后追踪，保持可射击距离。
- `ATTACK`：方向对齐且射线无友军时开火。
- `BREAK_WALL`：目标被砖墙阻挡时尝试破墙。
- `EVADE`：侦测到正面来弹时尝试转向或进入掩体。
- `STUCK_RECOVERY`：连续 500 毫秒无位移时重新选路。
- `DISABLED`：冻结、眩晕或混乱状态。
- `DESTROYED`：播放爆炸并结算分数。

### 9.3 AI 感知与性能

- 视野距离：普通敌人 8 格，狙击敌人 12 格。
- 视线检测：沿四方向做网格射线检测，钢墙和砖墙阻挡视线，草地降低发现距离。
- A* 寻路只在目标改变、路线阻塞或每 500～800 毫秒触发一次。
- 同屏敌人首版上限建议 12 个。
- 敌人射击加入 100～350 毫秒随机误差，避免机械式同时开火。
- 简单难度降低追踪频率；困难难度增加包抄倾向，不只增加血量。

## 10. 地图与地形

### 10.1 地图规格

- 逻辑网格：26 × 26 格。
- 单格逻辑尺寸：32 × 32 像素。
- 游戏世界尺寸：832 × 832 像素。
- 显示时按窗口等比缩放，保持像素整数倍或近似整数倍。
- 外围 HUD 不占用游戏世界坐标，避免改变碰撞逻辑。

### 10.2 地形规则

空地 `0`：

- 坦克和炮弹均可通过。

砖墙 `B`：

- 阻挡坦克和普通炮弹。
- 每块生命值为 2；受击后显示破损状态，第二次受击被摧毁。
- 火焰可点燃并在 1.5 秒后摧毁。
- 修复技能可恢复或临时生成砖墙。

钢墙 `S`：

- 阻挡坦克和普通炮弹。
- 普通炮弹不可摧毁；反弹弹可反弹。
- 后续可加入强化穿甲弹对钢墙造成有限破坏。

水域 `W`：

- 坦克不可进入，炮弹可飞越。
- 水面具有低成本像素波纹动画。

草地 `G`：

- 坦克和炮弹均可通过。
- 草地位于坦克上层渲染，可遮挡坦克轮廓。
- 玩家在草地中静止 0.6 秒后降低敌人发现距离。

冰面 `I`（后续扩展）：

- 坦克可进入，但停止输入后继续滑行 0.25～0.4 秒。

基地核心 `H`：

- 玩家需保护的目标，建议生命值为 5。
- 被摧毁立即失败。

生成点 `E/P`：

- `E` 为敌人生成点，`P` 为玩家生成点。
- 出生点必须与障碍物保持至少一格安全距离。

### 10.3 LXY 中央签名布局

中央区域使用砖墙组成 `LXY`。以下 7 × 17 点阵中，`#` 表示砖墙，`.` 表示空地：

```text
#.... #...# #...#
#.... .#.#. .#.#.
#.... ..#.. ..#..
#.... ..#.. ..#..
#.... ..#.. ..#..
#.... .#.#. ..#..
##### #...# ..#..
```

实现要求：

- 图案整体位于地图中央附近，不挡住所有主通道。
- LXY 砖墙可以被摧毁，让玩家主动改变路线。
- 外围可加入少量钢墙作为“字框锚点”，即使部分砖墙被毁仍能看出构图。
- 开局镜头用 1 秒轻微聚焦或高亮提示 LXY，确保身份标识可被注意到。
- 签名区域清除其他地形干扰，签名砖块具有青色描边与 3 点耐久；HUD 同时显示 `LXY DEFENSE`。

### 10.4 “浪尖大学社区”底图

- 在地板图层绘制完整文字“浪尖大学社区”。
- 建议采用大号像素字或块状无衬线字，横向居中或以两行排布。
- 颜色使用低对比蓝灰色，默认透明度 8%～12%。
- 文字位于地形和单位下层，不参与碰撞，不影响炮弹和敌人识别。
- 暂停页、标题页或右侧 HUD 再显示一次高对比品牌文字，确保主题清晰。
- 文字边缘可加入水浪像素纹理，强化“浪尖”社区主题，但不能降低战斗区域可读性。

### 10.5 首张地图结构

- 顶部 3 个敌人出生点，彼此间隔至少 6 格。
- 底部中央为基地核心，外围有 U 形砖墙保护。
- 中央 LXY 构成中场掩体和三条主要通路。
- 左侧以水域形成狭窄桥口，适合地雷和穿透弹。
- 右侧以草地和砖墙形成伏击区，适合近战火焰和无人机。
- 两条钢墙斜向分布，为反弹弹提供明确教学角度。
- 地图必须至少存在两条抵达基地的路线，避免 AI 完全堵死。

## 11. 技能与拾取系统

### 11.1 通用规则

- 技能来源包括地图随机技能箱、精英掉落和波次结束三选一。
- 武器类技能占用“弹药槽”，主动类技能占用“战术槽”。
- 同时装备 1 个弹药技能和 1 个主动技能，避免键位和规则过载。
- 拾取重复技能时，可增加持续时间、弹药数或等级。
- 技能箱刷新前先显示落点提示，避免突然出现在坦克下方。
- 技能效果必须用颜色、图标、音效和文字四种方式中至少两种表达，不能只依赖颜色。

### 11.2 首版基础技能

分裂弹 `split_shot`：

- 炮弹飞行 280 像素或玩家再次按下射击键时，分裂成 3 颗小弹。
- 小弹角度为主方向的 `-25° / 0° / +25°`，但最终碰撞仍按连续坐标计算。
- 每颗小弹伤害 1，分裂后不可再次分裂。
- 建议弹药数 6 发。

反弹弹 `ricochet`：

- 碰到砖墙或钢墙后按法线反射。
- 首版最多反弹 2 次，每次反弹后伤害不变、速度降低 8%。
- 玩家自己的反弹弹在 300 毫秒保护期后可伤害自己，保留风险与技巧。
- 建议弹药数 8 发。

穿透弹 `piercing_shot`：

- 可穿透最多 3 个敌人。
- 每穿透一个敌人后伤害降低 20%，最低伤害为 1。
- 不能穿透钢墙，可一次性击穿完整砖墙。
- 建议弹药数 5 发。

冰冻弹 `freeze_shot`：

- 命中后冻结普通敌人 3 秒。
- 首版采用“冻结结束后恢复，补枪可击毁”的规则，避免过强。
- Boss 只减速 40%，持续 1.5 秒。
- 建议弹药数 5 发。

时间减速 `time_slow`：

- 敌人、敌方炮弹和环境动画速度降至 50%，玩家保持正常速度。
- 持续 5 秒，冷却 20 秒。
- UI 使用蓝紫色计时环，结束前 1 秒闪烁提示。

空袭 `airstrike`：

- 以玩家触发位置为中心选取半径 5 格区域。
- 0.8 秒预警后落下 5～8 枚炸弹。
- 每个落点周围 1 格造成 2 点伤害，并伤害砖墙。
- 每关最多获得 2 次，避免成为无脑清屏工具。

地雷 `landmine`：

- 在玩家当前位置放置，敌人进入 0.6 格触发范围后爆炸。
- 对周围 1 格造成 3 点伤害。
- 持续 10 秒，最多同时存在 3 颗。
- 玩家不会触发自己的地雷。

修复砖墙 `repair_wall`：

- 修复玩家正前方 2 格内已有砖墙。
- 空地可生成临时砖墙，持续 15 秒。
- 不允许在坦克、基地、生成点、水域或技能箱上生成。
- 冷却 12 秒。

传送门 `teleport`：

- 立即传送到随机安全空地。
- 落点与敌人、敌方炮弹、基地至少保持 2 格距离。
- 落地对周围 1 格敌人眩晕 2 秒。
- 触发时先锁定候选格，找不到安全格则不消耗技能。

### 11.3 首版扩展技能

连锁闪电 `chain_lightning`：

- 首次命中后自动跳向 4 格内最近敌人，最多跳 3 次。
- 伤害建议为 `2 → 1.5 → 1`。
- 目标不能重复，跳跃路径用像素闪电线表现。

火焰喷射 `flamethrower`：

- 持续 3 秒，每 100 毫秒产生短程火焰粒子。
- 射程 3 格，可点燃砖墙，对同一敌人设置伤害间隔。
- 使用期间移动速度降低 15%。

混乱弹 `confusion`：

- 普通敌人方向控制反转，并将最近敌军视为攻击目标，持续 4 秒。
- 精英敌人持续 2 秒；Boss 免疫敌我反转，仅降低射击精度。
- 被混乱敌人击毁其他敌人时，玩家获得 70% 分数。

召唤僚机 `drone`：

- 跟随玩家 8 秒，每 700 毫秒攻击最近敌人。
- 单发伤害 1，射程 7 格。
- 无人机不参与实体阻挡，可被敌弹击毁。

紧急维修 `heal`：

- 立即恢复 2 点玩家装甲，不超过最大生命值。
- 满生命时使用不会消耗技能。

能量护盾 `shield`：

- 玩家 5 秒内免疫全部伤害，并显示清晰的青色护盾环。
- 只保护玩家坦克，不保护基地。

火力超频 `overdrive`：

- 持续 7 秒，提高玩家移动速度和主炮射速。
- 与特殊弹药组合时仍会消耗正常弹药数。

EMP 脉冲 `emp`：

- 普通敌人停机 2.5 秒，Boss 只停机 1 秒。
- 不直接造成伤害，定位为紧急控场技能。

### 11.4 技能平衡原则

- 同一技能不能同时承担高伤害、强控制和低风险三个优势。
- 全屏或自动索敌技能应限制次数或较长冷却。
- 控制技能对 Boss 使用衰减版效果，避免跳过机制。
- 所有随机掉落都设置保底：连续两波未出现恢复类或控制类技能时，提高其权重。
- 每个技能的数据放入独立配置对象，支持不改代码调整伤害、冷却、弹药数和稀有度。

### 11.5 LXY 浪尖共鸣

- 击毁敌人积累共鸣能量，重装和反弹坦克提供更多能量。
- HUD 显示独立的 `LXY 浪尖共鸣` 进度条。
- 能量达到 100% 后自动触发，不额外增加操作按键。
- 触发时清除全部敌方炮弹、冻结全场敌人 1.1 秒，并将基地修复 1 点。
- 基地满耐久时仍会清弹和控场，并额外获得 300 分。
- 共鸣从中央 LXY 图案向外扩散青色冲击环，使身份标识成为实际玩法系统。

## 12. 碰撞与伤害系统

### 12.1 碰撞对象

- 坦克与地图边界。
- 坦克与砖墙、钢墙、水域、基地。
- 坦克与坦克。
- 炮弹与墙体、坦克、基地、地雷。
- 爆炸范围与坦克、砖墙、基地。
- 拾取物与玩家。

### 12.2 判定方案

- 坦克主体使用略小于贴图的轴对齐矩形碰撞盒，减少“看起来没碰到却卡住”的感觉。
- 炮弹使用圆形或小矩形碰撞盒。
- 高速炮弹采用连续碰撞检测：比较上一帧到当前帧的线段与目标碰撞盒，避免穿墙。
- 地图采用 Tilemap 网格做粗筛，实体碰撞盒做精确判定。
- 同一炮弹在同一帧只能对同一目标结算一次伤害。
- 爆炸先收集目标，再统一结算，避免遍历过程中删除对象造成遗漏。

### 12.3 阵营与友伤

- 首版普通玩家炮弹不伤害玩家自己。
- 反弹弹在安全时间结束后可以伤害玩家自己。
- 敌方炮弹默认不伤害其他敌人；混乱状态下可造成敌军伤害。
- 空袭和地雷不伤害玩家，但会破坏砖墙。
- 玩家炮弹和所有玩家技能绝对不能伤害“浪尖核心”；只有敌方阵营炮弹可以降低基地耐久。
- 所有规则通过阵营掩码配置，不在碰撞回调中写大量例外判断。

## 13. 胜负判定

胜利条件：

- 守卫模式中依次完成六个关卡并击毁最终 Boss。
- 最终关只配置一只 Boss，击毁后直接结算胜利。

失败条件：

- 玩家生命值降至 0，且没有复活次数。
- “浪尖核心”生命值降至 0。
- 特殊挑战模式倒计时归零且目标未完成。

判定优先级：

1. 若基地与最后一个敌人在同一帧同时被摧毁，先结算基地失败，避免规则歧义。
2. 游戏进入 `VICTORY` 或 `DEFEAT` 后停止生成敌人和伤害事件。
3. 保留 800 毫秒慢动作展示最后爆炸，再显示结算页。

## 14. UI/UX 设计

### 14.1 视觉方向

- 战场：16/32 位像素风，硬边缘、有限色板、像素粒子。
- UI：现代扁平化卡片，圆角 10～14 像素，轻阴影，信息层级明确。
- 主色：深海蓝 `#14213D`。
- 品牌色：浪尖青 `#25D0C8`。
- 玩家色：亮金黄 `#FFD166`。
- 敌军色：珊瑚红 `#EF476F`。
- 技能色：电光紫 `#8B5CF6`。
- 地面色：深灰蓝 `#1C2733`。

### 14.2 页面结构

标题页：

- 大标题“坦克防线”。
- 副标题“浪尖大学社区 · LXY”。
- 开始游戏、模式选择、操作说明、音效开关。
- 背景使用低速移动的像素水浪与坦克剪影。

战斗页：

- 中央为正方形战场。
- 左上角显示玩家生命、护盾和当前连击。
- 顶部中央显示波次、剩余敌人和倒计时。
- 右上角显示分数和最高分。
- 底部显示主武器、弹药技能、主动技能和冷却。
- 右侧可显示敌人剩余图标，但小屏幕时折叠。

暂停页：

- 背景模糊或加深，不完全隐藏战场。
- 继续、重新开始、操作说明、返回主页。

结算页：

- 胜利或失败标题。
- 总分、击毁数、命中率、最高连击、基地剩余生命。
- 本局获得的技能图标。
- 再来一局、下一关、返回主页。

### 14.3 明确反馈

- 炮弹命中：短促闪光、火花、轻音效。
- 击毁：爆炸、分数向上浮动、轻微震屏。
- 技能可用：图标发亮并播放短提示音。
- 技能不可用：按钮抖动并显示剩余冷却时间。
- 无法移动：接触方向出现碰撞火花或轮带摩擦动画。
- 敌人锁定：危险方向出现短暂红色边缘提示。
- 暂停、胜利、失败必须显著改变画面状态，不能只显示小字。

### 14.4 可访问性

- 重要状态不只用红绿颜色区分，额外使用图标和文字。
- 提供震屏强度、音量和粒子数量设置。
- 支持键位提示，后续可加入键位自定义。
- 页面失去焦点时自动暂停，避免玩家切换标签页后被击毁。

## 15. 音效与动效

- 普通开火：短促 8-bit 脉冲音。
- 重炮/空袭：低频爆破音，但限制峰值音量。
- 命中钢墙：清脆金属音。
- 技能拾取：上扬琶音。
- 生命危险：低频提示，每 2 秒最多一次。
- 首版不制作背景音乐；背景音乐作为后续可选增强项。
- 同一音效做 3～5 个轻微音高变体，减少重复感。
- 音频必须由用户首次点击后启动，符合浏览器自动播放限制。

## 16. 技术选型

### 16.1 推荐栈

- 构建工具：Vite。
- 开发语言：TypeScript。
- 游戏引擎：Phaser 3。
- UI：HTML/CSS 覆盖层，复杂菜单可使用轻量组件化代码；首版不强制 React。
- 地图：Phaser Tilemap，地图数据使用 JSON/二维数组。
- 测试：Vitest 负责纯逻辑单元测试，Playwright 负责关键浏览器流程。
- 代码规范：ESLint + Prettier。
- 包管理器：npm。

选择原因：

- Phaser 已提供场景、渲染、输入、音频、动画和碰撞等网页游戏常用能力。
- TypeScript 便于管理技能、敌人、地形和事件等复杂类型。
- Vite 启动快、配置少，适合生成静态网页并通过 GitHub Actions 部署到 GitHub Pages。
- HUD 使用 DOM/CSS 更容易实现现代扁平风格、响应式和可访问性。

### 16.2 浏览器支持

- Chrome、Edge、Firefox 最近两个主要版本。
- Safari 最近两个主要版本。
- 首版验收分辨率从 1280 × 720 起；小屏幕可显示“建议使用桌面浏览器”提示。
- WebGL 不可用时尝试 Canvas 渲染回退，并降低粒子数量。

## 17. 软件架构

### 17.1 场景划分

- `BootScene`：加载最小启动资源和全局配置。
- `PreloadScene`：加载图片、音频、字体，显示品牌化进度条。
- `MenuScene`：标题页、模式和难度选择。
- `GameScene`：地图、实体、碰撞、波次和战斗主循环。
- `UIScene`：独立 HUD，与 GameScene 通过事件总线通信。
- `ResultScene`：结算与重新开始。

### 17.2 核心模块

- `InputController`：统一键盘和触摸输入，输出四方向意图。
- `PlayerTank`：玩家移动、受击、武器和状态。
- `EnemyTank`：敌方属性与 AI 状态机。
- `ProjectileSystem`：对象池、飞行、反弹、穿透和命中。
- `CollisionSystem`：连续碰撞、阵营过滤和伤害事件。
- `TerrainSystem`：砖墙损坏、修复、草地遮挡和水域阻挡。
- `SkillSystem`：技能装备、释放、持续时间、冷却和掉落。
- `WaveDirector`：敌人波次、难度曲线和胜负触发。
- `ScoreSystem`：分数、连击、结算统计和本地最高分。
- `AudioManager`：音量、音效池和静音状态；首版不加载背景音乐。
- `GameStateStore`：当前局数据、设置和持久化。
- `EventBus`：游戏逻辑与 HUD 解耦。

## 20. 难度曲线

简单：

- 敌人射击前摇较长，追踪频率低。
- 技能箱刷新更频繁。
- 玩家初始生命 6，基地生命 6。

标准：

- 使用本文档默认数值。
- 敌人包含巡逻、快速、重装和狙击组合。

困难：

- 敌人协同行为增加，会从不同通道压迫基地。
- 敌弹速度提高约 10%，但必须保留可反应时间。
- 技能掉落略少，精英出现更早。
- 不建议单纯把敌人生命翻倍，以免战斗变拖沓。

关卡配置：

- 第 1 关：4 个普通坦克，教学移动与射击。
- 第 2 关：普通与快速坦克，教学守侧路。
- 第 3 关：重装与狙击加入，教学地形和技能。
- 第 4 关：快速、重装与反弹坦克形成混合压力。
- 第 5 关：精英混编部队，没有 Boss。
- 第 6 关：只出现一只潮汐巨兽，作为最终考验。

## 21. 性能目标

- 桌面端主流设备目标 60 FPS。
- 移动端性能作为后续优化指标，不列入首版完成条件。
- 同屏建议上限：12 敌人、40 炮弹、80 粒子、10 拾取/部署物。
- 炮弹、爆炸、伤害数字、火花使用对象池，避免频繁创建和销毁。
- AI 不逐帧寻路；寻路和视线检测分帧执行。
- 背景文字与静态地形预渲染到单独图层。
- 页面首次可交互目标小于 3 秒（正常宽带、压缩后首版资源）。
- 初始资源包建议控制在 10 MB 以内。

## 22. 存档与隐私

- 使用 `localStorage` 保存设置、最高分、最高波次和已解锁模式。
- 首版不要求账号系统和服务器数据库。
- 不采集姓名、手机号、位置等个人信息。
- 若后续加入排行榜，需要单独设计昵称审核、作弊防护和隐私说明。

建议存档键：

```text

```

## 23. 测试策略

### 23.1 单元测试

- 四方向输入互斥和最后按键优先。
- 坦克与各类地形的通行规则。
- 炮弹反射角和最大反弹次数。
- 穿透弹目标去重和伤害衰减。
- 冻结、减速、混乱的持续时间。
- 技能冷却、弹药消耗和重复拾取。
- 胜利/失败同帧触发时的优先级。
- 得分、连击和最高分计算。
- 随机传送安全落点筛选。
- 临时砖墙不能覆盖实体和关键格。

### 23.2 集成测试

- 玩家完整完成一关，选择一项技能奖励后进入下一关。
- 基地被摧毁后停止战斗并进入失败页。
- 最后一个敌人被击毁后进入胜利页。
- 暂停后 AI、炮弹、计时器和技能持续时间全部冻结。
- 页面失焦自动暂停，恢复后不会跳帧造成瞬间伤害。
- HUD 与实际生命、分数、弹药、冷却一致。

### 23.3 人工体验测试

- 新玩家能否在 30 秒内理解移动和射击。
- LXY 在开局和战斗中是否清晰可辨。
- “浪尖大学社区”背景是否明显但不干扰单位识别。
- 砖墙损坏阶段是否容易看懂。
- 反弹弹是否有技巧感且不会造成过多意外自杀。
- 草地遮挡是否公平，敌人攻击是否有预警。
- Boss 攻击是否有足够前摇和躲避空间。

- 地图中央障碍物组成可辨认的 `LXY`。
- 地图底图完整显示“浪尖大学社区”。
- 标题、战斗、暂停、结算四类界面完整。
- 页面失焦时自动暂停。

- 1080p 桌面浏览器中稳定接近 60 FPS。
- 1280 × 720、1920 × 1080 桌面浏览器中主要 UI 不遮挡战场。
- 游戏主流程无阻塞性错误，连续完成 10 局无崩溃。

## 26. 风险与处理方案

范围过大：

- 13 个技能全部首发会显著增加碰撞、AI 和平衡工作量。
- 处理：保留一个弹药槽和一个主动槽，并通过弹药数量、一次性主动技能和刷新频率约束强度。

画面混乱：

- 像素背景文字、草地、爆炸和现代 HUD 同时出现可能影响识别。
- 处理：背景低对比、战斗单位高轮廓、危险效果统一色彩规范。

AI 卡住：

- 可破坏和临时生成墙体会使预计算路径失效。
- 处理：地图变更后标记导航网格版本；敌人发现版本变化时重新寻路。

反弹弹失控：

- 多颗炮弹反弹会造成性能和公平性问题。
- 处理：限制反弹次数、生命周期和同屏数量，并给玩家短暂自伤保护期。

移动端操作拥挤：

- 技能过多会让虚拟按钮难以使用。
- 处理：只装备一个弹药技能和一个主动技能，其他技能通过切换或自动触发处理。

字体与素材授权：

- 像素字体和音频可能存在授权问题。
- 处理：优先使用 SIL OFL、CC0 或自制素材，并在项目中维护 `ASSET_LICENSES.md`。

## 27. 首版建议冻结范围

为了尽快获得一个“能玩、好看、可继续迭代”的版本，建议首版冻结为：

- 1 张 26 × 26 的 LXY 主题地图。
- 1 个守卫模式，6 个独立关卡。
- 1 辆玩家坦克。
- 4 种普通敌人 + 1 个 Boss。
- 砖墙、钢墙、水域、草地 4 种地形。
- 首版上线 17 种技能，每关结束从随机三项中选择一项。
- 标题页、战斗 HUD、暂停页、结算页。
- 桌面浏览器键盘操作；移动端横屏操作后续补充。
- 本地最高分和设置保存。

第二阶段再加入无尽模式、更多地图、更多 Boss、双人合作和排行榜。

## 28. 已确认的开发决策

1. 游戏正式名称为《坦克防线》。
2. 背景文字为完整的“浪尖大学社区”。
3. 地图身份标识为 `LXY`，展示时大小写均可；实现中统一使用 `lxy` 资源标识。
4. 首版只做网页端，以桌面浏览器为强制验收平台。

8. 项目代码托管到 GitHub，并通过 GitHub Pages 部署网页版。

## 29. GitHub 托管与部署方案

### 29.1 仓库建议

- GitHub 仓库名建议使用 `tank-defense`。
- 默认分支使用 `main`。
- 源码、文档、测试和素材许可记录都进入同一仓库。
- `dist/` 为构建产物，不手动提交到源码分支。
- 发布地址预计为 `https://<github用户名>.github.io/tank-defense/`。

### 29.2 Vite 路径配置

GitHub Pages 的项目站点带有仓库名前缀，因此生产构建需要配置正确的 `base`：

```ts
// vite.config.ts
import { defineConfig } from 'vite';

export default defineConfig({
  base: '/tank-defense/',
});
```

如果未来使用 `<github用户名>.github.io` 作为用户主页仓库，则 `base` 改为 `/`。

### 29.3 自动部署

- 使用 GitHub Actions 在每次推送到 `main` 后执行安装、测试和构建。
- 构建成功后将 `dist/` 上传为 Pages artifact，并部署到 GitHub Pages。
- 工作流所需权限限定为 `contents: read`、`pages: write` 和 `id-token: write`。
- 同一时间只保留一个生产部署，新的部署取消旧的未完成任务。
- 发布前必须先通过 `npm run test` 和 `npm run build`。

### 29.4 发布验收

- GitHub 仓库可以正常访问并包含 README、技术文档和素材许可记录。
- GitHub Actions 最新部署任务成功。
- Pages 地址可直接打开标题页，不出现资源 404 或空白页。
- 刷新游戏地址后仍可正确加载。
- Chrome 和 Edge 可完成一局完整流程。
- README 中记录在线试玩地址、操作说明、本地启动和构建命令。
